# 试用指标与数据口径

目的：判断本地 SSH 调查工具是否降低运维工作量，并保持结论可核对。目标人群已选定；目前没有客户基线、试用数据或收入数据。指标定义使用 Data 的 design-kpis 工作流设计，以下不是已测量成绩。

## 指标选择

候选指标包含处理时间、重要结论纠正、证据查阅、报告打开量、安装完成、重复使用、付费意愿、推理耗时和模型调用数。优先选择对继续投入有直接意义的三项；模型调用数量和报告打开量只作诊断，不能单独代表价值。

| 指标 | 定义与分母 | 数据来源/负责人 | 决策用途与局限 |
|---|---|---|---|
| 每案例人工有效处理时间 | 各方法已完成案例中 `active_review_seconds` 的中位数；包含核对与纠正，不含无人等待 | 操作人计时，复核人确认 | 比较工作量；必须同时报告完成率，避免排除困难案例后显得更快 |
| 重要结论纠正率 | 已人工复核的辅助报告中，至少有1处重要纠正的报告数 / 已复核辅助报告数 | 复核人逐案例记录 | 衡量误导负担；这是报告纠正率，不是攻击误报率或模型准确率 |
| 再次实际使用 | 在约定随访窗口内实际用于另一个授权案例的团队数 / 有后续案例机会且完成随访的试用团队数 | 团队联系人和项目负责人 | 判断持续价值；无后续案例机会者单列，不算拒绝；口头意愿不等于使用 |

可用于解释变化的诊断：安装完成时间、报告中被使用的证据项、模型响应等待时间。护栏：完成/超时/放弃率必须伴随时间指标报告；所有试用均应保持授权范围内只读处理，出现越权操作或未批准的数据外发即暂停。

## 重要纠正的操作定义

满足任意一项，由复核人计为重要纠正：将未知写成已确认事实；与来源记录冲突；把无证据关系写成确定关联；遗漏足以改变处置建议的关键信息。风格、标点或语言偏好不计入。只提出并清楚标记的待核对假设，不因最终被排除就自动记为错误事实；仍可记录其是否浪费调查时间。

## 数据粒度和比较

每条反馈对应一个匿名团队/操作者、一个案例、一个处理方法和一次尝试。方法为 `manual`、`facts_only` 或 `model_assisted`。记录模型/代码/背景版本以及展示顺序，区分授权历史案例和合成演示。

时间比较应使用难度相近、范围一致的案例；同一个人重复熟悉案例会产生学习效应。样本少时展示原始分布和案例差异，不给出普遍节省比例。`null` 表示未测量，不能改成0；未询问付费意愿不算“不愿意”。

## 目标与门槛

目前不设置未经基线支持的百分比目标。首轮先取得完整记录，再由参与团队确认什么程度的时间改善值得继续，哪些错误无法接受。授权范围和数据处理边界是操作约束，不是通过少量成功案例就能证明长期零风险。

反馈样例 `examples/pilot-feedback-template.json` 标为 `is_template=true`，不得计入统计。实际记录应在取得反馈后填写；将 `is_template` 改为false不代表记录已经被独立审核。

## 当前证据与缺口

- 已有证据：用户选定目标为 Linux 运维／小型企业内网团队；此前本地模型流程已运行，但出现过度解释。
- 本轮工程结果：另行记录格式接入、结构约束和本地模型试跑；不能替代客户效果。
- 缺口：客户名单、授权生产案例、人工处理基线、独立复核、复用行为和真实付费记录。
- 所有人群效果、节省时间、纠正率和商业结论均为“待测量”，不能从模拟数据填入。
